WHY THIS ARCHITECTURE

家里轻量采集，云端保留历史。Collect at home. Keep history in your cloud.

这里的“自建托管”，指把网页、接口和长期历史部署到自己的 Cloudflare 账号；家庭主机专注于采集。Self-managed means hosting the dashboard, APIs and history in your own Cloudflare account, with the home host focused on collection.

  1. PVS6本地只读数据Read-only local data
  2. 采集主机Collector host采样 + SQLite 待上传队列Sampling + SQLite upload queue
  3. Workers + D1认证上传 + 长期历史Authenticated uploads + history
  4. 私有网页Private dashboardGitHub OAuth + 用户白名单user allowlist

家庭主机主动上传，网页只读取云端记录。断网时继续本地采集，恢复后补传；无需开放家庭网络入口。The home host uploads outbound; the dashboard reads cloud records. Collection continues offline and uploads resume later, without opening inbound home ports.

家里只运行必需的部分Keep the home host focused

主机负责只读采样、记录总发电、家庭用电、电网进出与单块面板功率、暂存待上传数据，不修改 PVS6 运行参数。长期历史存入 D1，家庭主机无需维护历史数据库或网页服务。The host reads PVS without changing operating settings, records total solar, home use, grid import/export and individual panel power, and buffers uploads. D1 stores history, so the home host needs no historical database or web server.

远程看历史，无需开放家庭入口Remote history. No open home ports.

网页从云端读取已上传记录，家庭主机主动向云端连接，不对外提供网页，也不用让云端直接访问 PVS。家庭外网中断时，采集器继续将本地读数入队，恢复后补传；云端可查看已上传历史，但实时读数会过期。The page reads uploaded records in the cloud. The home host initiates outbound connections and serves no public webpage; the cloud does not poll PVS. During a home internet outage the collector queues local readings for later upload. Uploaded history stays available, while cloud live readings become stale.

保留记录，也承担托管责任Own the record and its upkeep

代价是配置 Workers、D1、OAuth 和密钥，维护备份并观察用量。长期保留取决于云端容量和备份，云服务限额与费用按供应商条款计算。You configure Workers, D1, OAuth, and secrets, keep backups, and watch usage. Long-term retention depends on cloud capacity and backups; provider terms determine limits and costs.

为什么没有选择 Home Assistant？Why not Home Assistant?项目聚焦 PVS6 历史和私有网页。HA 方案会让采集、实体和展示依赖家庭自动化平台，有些历史方案还需要 InfluxDB。若你已经使用 HA，或需要联动更多设备，现成的 PVS 集成是合理的选择。本项目则为单一监控用途保留更小的家庭运行栈。The goal is PVS6 history and a private webpage. HA-based routes couple collection, entities, and presentation to that platform; some history stacks add InfluxDB. If you already use HA or want device automation, its PVS integrations are a sensible choice. This project chooses a smaller home runtime for a specific monitoring use case.

为什么面板记录每 5 分钟一次？Why record panels every five minutes?总发电功率、家庭用电功率和电网进出功率约每 10 秒读取，汇总成一分钟历史；单块面板约每 5 分钟读取。面板设备本身的更新节奏较慢，加快查询不一定得到新数据。缓存分组查询和分层采集，是为了兼顾观察变化、存储用量与 PVS 处理器负担；并不是把 5 分钟说成硬件的最高能力。Total solar power, home-use power and grid import/export power are read about every 10 seconds and rolled into minute history. Individual panels are read about every five minutes. Panel devices update more slowly, so faster queries may not yield new data. Cached, tiered reads balance visibility, storage and PVS CPU load; five minutes is not a claim about the hardware’s maximum capability. 官方查询建议Official query guidance ↗

READING THE DATA

数据含义与功能边界。What the data can tell you.

家庭负载来自 PVS 上报；校准后的电网与家庭用电是估算值。缺失或过期读数不会当作零，天气模型也不能替代功率测量。天气数据使用 Open-Meteo 的非商业免费服务，遵循其条款。Home load comes from PVS readings; calibrated grid and home values are estimates. Missing or stale readings are never treated as zero. Weather is a model forecast, not a power measurement, and uses Open-Meteo’s free non-commercial service under its terms.

可选 Bark 通知监测站点读数缺失或无效，并发送异常与恢复提醒；不能据此确定是采集器、网络还是 PVS 故障，也不检测面板低产出。面板视图提供记录与状态供你判断，不做自动故障诊断。历史从采集开始积累，不导入旧官方历史。Optional Bark notifications monitor missing or invalid site readings and send alert and recovery messages. They cannot identify whether the collector, network or PVS failed, and do not detect panel underperformance. Panel views provide records and reporting states for manual assessment, without automatic fault diagnosis. History starts with collection and does not import old vendor history.

手机通知通过 Finb 与贡献者开发的开源 iOS 应用 Bark 及其推送 API 送达，感谢他们提供的通知服务。Phone delivery uses Bark, the open-source iOS app and push API by Finb and contributors. Thank you to the Bark community for providing this notification service. Finb/Bark ↗ · 通知配置与限制Notification setup & limits ↗
